## 四、关键决策（5 项，需用户拍板）

### 4.1 LLM Provider 选择 ❓

| 选项 | 优 | 劣 | 建议 |
|---|---|---|---|
| **A. Claude API** | 工具调用最稳 | 贵 + 国内访问不便 | ❌ |
| **B. DeepSeek API** | 便宜、OpenAI 兼容、工具调用可用 | 数据出境合规需评估 | ✅ 建议 |
| **C. Qwen3.5-8B 本地** | 完全离线、便宜 | 需要 GPU 部署；效果弱于 Claude | ❌ 仅生产环境可考虑 |
| **D. Mock 占位** | 不依赖外部 | 不能真实"问" | ✅ 第 1 阶段先用此，跑通链路 |

**我的建议**：**D → B 渐进**——先用 Mock 跑通完整链路，再接 DeepSeek。

### 4.2 第 1 步目标 ❓

| 档位 | 内容 | 工作量 | 价值 |
|---|---|---|---|
| **A. 文档级** | 继续完善设计、SQL、API 草图 | 1-2 天 | 低 |
| **B. 骨架级** | 包结构 + 接口 + Mock 实现 + 单元测试 | 1 周 | 中 |
| **C. MVP 级** | 1 个完整 Tool + 1 个 REST 端点，能真实查 AGP | 2 周 | **高（推荐）** |
| **D. 生产级** | 17 Tool + Orchestrator + REST + 鉴权 + 部署 | 3-4 周 | 最高 |

**我的建议**：**C**——实现 `execute_wt_select` + `POST /by-intent` 端点，能真正查 AGP 元数据库，验证链路。

### 4.3 是否需要 Mock Backend ⚓

| 选项 | 优 | 劣 |
|---|---|---|
| **A. 全部连真实后端** | 真实测试 | 强依赖外部；没网就废 |
| **B. Mock Backend** | 本地能跑；CI 能跑 | 测的是 mock 而非真实 |

**我的建议**：**B 必须有**——`MockStarRocksBackend` / `MockWTSqlBackend` / `MockHttpTsdBBackend` 各一个，通过 `@Profile("dev")` 切换。

### 4.4 包命名 ❓

| 选项 | 建议 |
|---|---|
| `com.talent.query.*` | ✅ 与现有 `com.talent.job.*`、`com.talent.server.*` 平级 |
| `com.talent.intelligentquery.*` | ❌ 太长 |
| 独立新包 | ❌ 不一致 |

**决定**：**`com.talent.query.*`**。

### 4.5 项目最终目标 ❓

| 选项 | 含义 | 影响 |
|---|---|---|
| **Demo / 学习** | 仅供团队学习/演示 | 可以简化审计/权限/部署 |
| **学习 + 实际生产** | 这套代码未来要进生产 | 必须全功能 + 部署文档 |

**我的理解**：当前项目 WISETao_custom_demo 是 demo 仓库，但 16 周 G3 阶段交付的智能问数要进"灵知"生产。**所以代码要按生产标准写**。
