# 工具实现规范（v3）

> **目的**：每个 Tool 实现者按此规范编码——定义输入参数校验、SQL 模板、返回格式、错误码、审计字段。
> **范围**：17 个 Tool（v3 集合），覆盖字典/时序/业务事实/AGP 元库/项目业务库/KG/RAG/规则/Skill/护栏 10 类。
> **v4 待扩展**：实体相关 Tool（entity_attribute_query / entity_360_view / entity_relation_query 等）将在 v4 规范中补充。

## 1. 通用规范（所有 Tool 必读）

### 1.1 输入参数校验

```yaml
通用规则:
  时间字段:
    类型: ISO8601 datetime
    必填: start_time, end_time
    校验: start_time < end_time
    时区: Asia/Shanghai (默认注入)
    跨度限制: <= 365天 (可配置 system.max-time-range-days)

  字符串过滤:
    必填: tag_filter / wt_sql
    校验:
      - 必须为合法正则 / SQL
      - 长度 <= 1024
      - 禁止包含 ";", "--", "/*" SQL 注入特征

  数组参数:
    tag_names: ["tag1", "tag2", ...]
    限制: 长度 1-1000
    去重: 自动去重
    校验: 所有 tagName 必匹配 WT_TAG 实际存在 (查 WT_TAG)

  数值参数:
    interval_seconds: >= 1
    limit: 1 <= limit <= 10000
    sample: 1 <= sample <= 10000
```

### 1.2 返回格式（AGP 标准）

```java
public class ToolResult {
    boolean success;             // true=成功, false=失败
    String  toolName;            // 工具名 (e.g. "aggregate")
    String  apiOrSql;            // 实际调用的 WT-SQL 或 HTTP URL
    JsonNode params;             // 入参（用于审计）
    JsonNode fields;             // ★ 字段元数据 [{name, title, type}]
    JsonNode data;               // ★ 数据行数组 [{字段: 值}]
    int     rowCount;
    long    executionMs;
    String  auditId;             // 写审计后回填
    Map<String,String> citations; // 引用溯源 source_id / page / chunk_id
    String  errorMessage;        // 失败时填充
    String  errorCode;           // 见 §1.4
    PageInfo page;               // 分页 {pageNum, pageSize, pageTotal, itemTotal}
}
```

> **强制约定**：`fields` + `data` 必须符合 AGP 规范（0903 会议定义），前端可直接渲染。

### 1.3 质量过滤（强制）

**所有时序 SQL 必须带**：
```sql
WHERE bitand(a.quality, :bad_value_mask) != :bad_value_mask
-- 默认 :bad_value_mask = 128 (AGP 默认)
-- 可由 system.bad-value-mask 配置覆盖
```

★ **质量位 2 字节 4 nibble 解码**（第五轮 TSDB 厂商手册 V2.2，答案解释用）：

| nibble（低→高） | 含义 | 问数可用掩码 |
|---|---|---|
| 低 4 位 | OriginalStatus：GOOD/NODATA/CREATED/SHUTDOWN/CALCOFF/**BAD**/DIVBYZERO/REMOVED/DISABLED | `bitand(q,128)` 剔除 BAD（128=低 nibble bit7） |
| 次 4 位 | DataSrc：RAWDATA(现场)/HANDIN(手工录入)/ALCULATED(计算) | `bitand(q, 0x0200)` 区分手工 vs 计算 |
| 次 4 位 | OPC 状态 | — |
| 高 4 位 | CurStatus：NORMAL/超I·II级上下限/DALARM/ALARMCONFIRM(已确认)/NOTGOOD/HITALARMSCRIPT | `bitand(q, 0x8000)` 判告警态 |

→ 涉及"这个数是手抄的还是算出来的""是否处于告警"类问题按上表扩展掩码；全部生产 SQL（源码实证）统一用 `bitand(quality,128) != 128 and value > 0` 三件套。

### 1.3.1 ★ tagName 四段式编码（第六轮源码实证，全部正则/解析模板的根基）

```
tagName = [前缀]_tagCode_粒度段_device
  粒度段首位 = 点类型：1=模拟量 ANALOG，2=状态量 DIGIT/STATUS
  粒度段末位 = 粒度：O=原始，H/D/M/Y=小时/天/月/年派生
实例：HWNBYC174_1O_DEV001（模拟量原始）· HWNBYC042_2O_DEV001（状态量）· zcdllsl_1H_100620000005933（小时派生）
```

- **StarRocks 解析用 1 基下标**：`split(tagName,'_')[1]`=tagCode、`[3]`=device——NL2SQL 生成 split 表达式**禁止 0 基**；
- 生产 SQL 标准三件套（照抄源码）：`left join WT_TAG b on a.tagIndex=b.tagIndex` + `regexp(tagName,'^Xxx_1O_')`（**带 ^**）+ 质量过滤；
- 点位类型过滤：模拟量 `_1O_` / 状态量 `_2O_`；粒度直接匹配中段。

### 1.4 错误码

| errorCode | 含义 | LLM 应如何处理 |
|---|---|---|
| `INVALID_PARAM` | 参数不合法（缺字段、类型错）| 重试，修正参数 |
| `PERMISSION_DENIED` | 字段/行级权限不足 | 用其他字段重试或放弃 |
| `SENSITIVE_TABLE` | 命中敏感表白名单 | 改用 `replacement_tool` 重试 |
| `DML_FORBIDDEN` | 检测到 INSERT/UPDATE/DELETE/DDL | 拒绝，必须只读 |
| `EXCEED_LIMIT` | 时间跨度/扫描行数超阈值 | 缩小时间范围 |
| `BACKEND_DOWN` | 后端不可达 | 报错，等用户重试 |
| `WT_SQL_PARSE_ERROR` | AGP 不接受该 WT-SQL | 简化 SQL，去掉不支持特性 |
| `TAG_NOT_FOUND` | tagName 不在 WT_TAG | 用 `lookup_tag` 先查 |

### 1.5 审计字段（强制）

每次 Tool 执行完成（成功或失败），写一行 `WT_QUERY_AUDIT`：

```sql
INSERT INTO WT_QUERY_AUDIT (
    audit_id, user_id, app_id, org_id,
    question, sql_text, api_url, api_params,
    row_count, execution_ms,
    error_code, error_message,
    result_hash, prev_hash, created_at,
    tool_name, tool_layer  -- ★ v3 新增：标识调用的 Tool 名和接口层级
) VALUES (
    :audit_id, :user_id, :app_id, :org_id,
    :question, :wt_sql, :api_url, :params_json,
    :row_count, :execution_ms,
    :error_code, :error_message,
    SHA256(:wt_sql || :result_json),    -- 哈希链
    (SELECT result_hash FROM WT_QUERY_AUDIT 
     WHERE user_id=:user_id ORDER BY audit_id DESC LIMIT 1),
    NOW(),
    :tool_name, :tool_layer
);
```

### 1.6 接口层级（v3 强制约束）

| 层级 | 含义 | 占比目标 | Tool 标注示例 |
|---|---|---|---|
| `metadata` | 元数据/IoT 基础接口 | ~20% | `lookup_entity`, `latest_value`, `lookup_tag` |
| `base_business` | 基础业务接口 | ~60% | `aggregate`, `execute_wt_select`, `search_knowledge` |
| `scenario` | 场景业务接口（行业通用）| ~15% | `agp_preset_interface`, `wide_history` |
| `project` | 项目应用接口 | ~5% | `business_metrics`（派生表）|

> 校验层强制：80%+ 调用走前 2 层，project 层仅在前 3 层查不到时才调。

## 2. 字典类 Tool（3 个）

### 2.1 `lookup_metric` (P0, layer: metadata)

```yaml
description: |
  查指标字典表 WT_METRIC_DICT，获取业务指标名称、计算公式、单位、采集点等元数据。
  在用户问"什么叫 XX 指标？"、"PR 怎么算？"、"有哪些指标？"时调用。

input:
  keyword: 业务关键词（如 "发电量"、"离散率"、"PR"），可选
  category: 指标分类（electricity/dispatch/safety/maintenance），可选

backend: StarRocksBackend (WT_METRIC_DICT 表)

sql: |
  SELECT code, name, category, formula, granularity, unit,
         source_tags, description
  FROM WT_METRIC_DICT
  WHERE (:keyword IS NULL 
         OR name LIKE CONCAT('%', :keyword, '%') 
         OR code LIKE CONCAT('%', :keyword, '%') 
         OR description LIKE CONCAT('%', :keyword, '%'))
    AND (:category IS NULL OR category = :category)
  LIMIT 50

seed 口径（第六轮源码 + 第五轮 SK 文档，公式字段直接灌入）:
  - 限电损失: lossSumValue = 样板机日均电量×全站设备数 − 全站实发（样板机=pvConfig"箱变样板机"5 台）
  - 低效组串: score = (组串日发电 − 全体均值)/全体标准差，低效判定 score ≤ −2（z-score 法，
    与"离散率四级评级 ≤5%/≤10%/≤20%/>20%"是两套并行算法——前者点名组串，后者评方阵）
  - 故障损失: 仅统计 8–20 点（配置"故障损失电量计算开始/结束小时"），状态段>7200s 视为断数，
    损失电量=故障窗口内同箱变(subId)其他逆变器插值
  - 灰尘影响: fullRatio(样板机理论比) vs actualRatio(全站实际比)，5 分钟探针 min_by
  - PR 综合效率: QZXN26 = 上网电量/(辐照×装机)；理论发电量 QZXN27；四级损耗链 QZXN22/28/29/23 + 等价时
  - 储能损耗族: 变配电损耗 QZXN43=(下网−充电)+(放电−上网)−站用电；综合效率 QZXN44=上网/下网；
    损耗率 QZXN45=(充电−放电)/下网；充放电转换效率 QZXN48=放电/充电（分母 0 跳写——除零保护）
  - PCS 可靠性: 运行小时 QZXN52=(充+放时长)×1430/150000/3600；计划停运系数 QZXN53（天粒度统计时间封顶 24h）；
    利用系数 QZXN56=运行小时/(8h×天数)。★ 1430/150000 在 SQL 硬编码，答案须声明口径来源

returns: List<MetricInfo>
  MetricInfo:
    code: string  # 业务编码 e.g. "HwStringILsl"
    name: string  # 中文名 e.g. "华为组串电流离散率"
    category: string
    formula: string  # 计算公式
    granularity: string  # 适用粒度（hour/day/month/year）
    unit: string  # 单位（kWh/%/m³/min）
    source_tags: List<string>  # 来源 tagName 正则数组
    description: string

errors:
  - WT_METRIC_DICT 表不存在 → 返回空列表 + warn 日志（不报错）
  - keyword 长度超 100 → INVALID_PARAM

audit_fields:
  - sql_text: SELECT ... FROM WT_METRIC_DICT WHERE ...
  - params: {keyword, category}
  - row_count: 返回条数
```

### 2.2 `lookup_entity` (P0, layer: metadata)

```yaml
description: |
  查实体字典，支持按业务名/类型/父级查 AGP 11 类基础模型实例。
  用户问"有哪些 XX？"、"钛能有哪些部门？"、"空压机 A 是什么？"时调用。
  ★ 增强：自动识别动态属性 → tagName 映射（0826 会议要求）。

input:
  keyword: 业务关键词，可选
  entity_type: 11 类基础模型之一（org/person/equipment/material/project/rule/document/environment/energy/iot/event），可选
  parent_id: 上级实体 ID（树形查询），可选
  include_dynamic_attrs: 是否包含动态属性（默认 true）

backend: StarRocksBackend (WT_DEVICE_DIM + WT_DYNAMIC_ATTR_MAP)

sql: |
  -- 第一段：查基础模型
  SELECT id, equipment_code AS code, equipment_name AS name,
         class_path AS entity_class, parent_id,
         NULL AS dynamic_attr_pattern
  FROM WT_DEVICE_DIM
  WHERE (:keyword IS NULL 
         OR equipment_name LIKE CONCAT('%', :keyword, '%') 
         OR equipment_code LIKE CONCAT('%', :keyword, '%'))
    AND (:entity_type IS NULL OR class_path LIKE CONCAT('%', :entity_type, '%'))
    AND (:parent_id IS NULL OR parent_id = :parent_id)
  
  UNION ALL
  
  -- 第二段：动态属性映射
  SELECT NULL, attr_code, attr_display, entity_class, NULL,
         tag_name_pattern
  FROM WT_DYNAMIC_ATTR_MAP
  WHERE :include_dynamic_attrs = true
    AND (:entity_type IS NULL OR entity_class = :entity_type)
  
  LIMIT 200

errors:
  - include_dynamic_attrs 越权 → PERMISSION_DENIED
```

### 2.3 `lookup_tag` (P0, layer: metadata)

```yaml
description: |
  查时序点位字典 WT_TAG，反查业务名↔tagName 映射。
  用户问"总电流对应的 tag"等具体测量点时调用。

input:
  keyword: 必填（点位名/中文名/注释）
  data_type: 0=整型/1=单精度/2=双精度/6=字符串，可选
  granularity: 1O/1H/1D/1M/1Y/2O，可选

backend: StarRocksBackend (WT_TAG 表)

sql: |
  SELECT tagName, tagIndex, dataType, comment
  FROM WT_TAG
  WHERE (tagName LIKE CONCAT('%', :keyword, '%') 
         OR comment LIKE CONCAT('%', :keyword, '%'))
    AND (:data_type IS NULL OR dataType = :data_type)
    AND (:granularity IS NULL OR tagName LIKE CONCAT('%_', :granularity, '_%'))

  LIMIT 100

★ granularity 语义（第六轮源码实证，与 tagName 四段式一致）:

  粒度段首位=点类型（1 模拟/2 状态），末位=粒度（O/H/D/M/Y）

★ seed 正则模板（pvConfig.json 生产实例，Few-shot 直接引用）:
  华为组串电流: ^HWNBYC(1(29|3[0-9]|4[0-9]|5[0-6]))_1O_*
  华为组串电压: ^HWNBYC(1(0[1-9]|1[0-9]|2[0-8]|))_1O_*
  阳光组串电流: ^YGNBYC(12[468]|13[02468]|14[02468]|15[02468]|16[02468]|17[02468])_1O_*
  阳光组串电压: ^YGNBYC(12[3579]|13[13579]|14[13579]|15[13579]|16[13579]|17[1357])_1O_*
  PCS 运行时长: ^CNPCSYY(43[7-9]|44[0-4])

★ tagCode 语义族（生产 SQL 实证，非自明缩写）:
  173/174=组串电流原始/小时日电量(华为) · 163=华为逆变器电网A相电流(非箱变!)
  053/054=阳光日/总发电量 · 163 箱变电流 tagCode=ZJGYC221 族
  zcdllsl/ZCDYLSV=组串电流/电压离散率 · NBQDLLSD1/NBQDLLSD2=逆变器电流/电量离散率

  - keyword 为空 → INVALID_PARAM
```

### 3.1 `latest_value` (P0, layer: metadata)

```yaml
description: |
  取某个或某批 tag 的最新实时值。
  走 TSDB HTTP `RTDQuery` 网关；兜底走 StarRocks max_by(timestamp)。

input:

backend: HttpTsdBBackend + StarRocksBackend 双路

flow:
  primary: GET /iotRealTimeValue?tagNames=...  (TSDB HTTP 网关)
  fallback: SELECT tagName, max_by(value, timestamp) AS val
            FROM WT_DATA JOIN WT_TAG ...
            WHERE tagName IN (...) 
              AND bitand(quality, 128) != 128
            GROUP BY tagName

errors:
  - 所有 tagName 都不存在 → TAG_NOT_FOUND
  - TSDB 网关超时 → 走 fallback
```

### 3.2 `time_series` (P0, layer: base_business)

```yaml
description: |
  时序明细查询，按时间桶聚合。
  支持 bucket: raw/1m/5m/15m/1h/1d。

input:
  tag_filter: 必填（正则匹配 tagName）
  start_time, end_time: 必填
  bucket: raw=原始 / 1m/5m/15m/1h/1d（默认 1h）
  limit: 1-10000（默认 1000）

backend: StarRocksBackend

bucket 映射:
  raw:    无聚合，明细返回
  1m:     time_slice(a.timestamp, INTERVAL 1 minute)
  5m:     time_slice(a.timestamp, INTERVAL 5 minute)
  15m:    time_slice(a.timestamp, INTERVAL 15 minute)
  1h:     date_trunc('hour', a.timestamp)
  1d:     date_trunc('day', a.timestamp)

sql (1h 桶示例):
  SELECT date_trunc('hour', a.timestamp) AS bucket,
         AVG(a.value) AS avgValue,
         MIN(a.value) AS minValue,
         MAX(a.value) AS maxValue,
         COUNT(*) AS sampleCount
  FROM WT_DATA a JOIN WT_TAG b ON a.tagIndex = b.tagIndex
  WHERE a.timestamp >= :start_time AND a.timestamp < :end_time
    AND b.tagName REGEXP :tag_filter
    AND bitand(a.quality, 128) != 128
  GROUP BY bucket
  ORDER BY bucket
  LIMIT :limit
```

### 3.3 `aggregate` (P0, layer: base_business)

```yaml
description: |
  时序聚合查询，SQL 端实现，支持 SUM/AVG/MAX/MIN/COUNT/STDDEV/VAR。
  ★ 必须支持 GROUP BY 维度（device / tagcode / bucket）。

input:
  tag_filter: 必填
  start_time, end_time: 必填
  func: 必填（SUM/AVG/MAX/MIN/COUNT/STDDEV/VAR）
  group_by: none/device/tagcode/bucket_hour/bucket_day/bucket_month（默认 none）
  bucket_interval: 5m/15m/1h/1d（仅 group_by 含 bucket_ 时生效）
  limit: 1-10000

backend: StarRocksBackend

group_select 映射:
  none:           "'all' AS bucket"
  device:         "tagNames[3] AS device"     # ★ split(tagName,'_') 数组 1 基下标（StarRocks 特性）
  tagcode:        "tagNames[1] AS tagCode"    # [0]=前缀段，[1]=tagCode，[2]=粒度段，[3]=device
  bucket_hour:    "date_trunc('hour', a.timestamp) AS bucket"
  bucket_day:     "date_trunc('day', a.timestamp) AS bucket"
  bucket_month:   "date_trunc('month', a.timestamp) AS bucket"

sql 模板:
  SELECT :group_select,
         :func(a.value) AS aggValue,
         COUNT(*) AS sampleCount
  FROM WT_DATA a
  JOIN WT_TAG b ON a.tagIndex = b.tagIndex
  WHERE a.timestamp >= :start_time AND a.timestamp < :end_time
    AND b.tagName REGEXP :tag_filter
    AND bitand(a.quality, 128) != 128
  GROUP BY :group_by_clause
  ORDER BY aggValue DESC
  LIMIT :limit

errors:
  - group_by=bucket_* 但 bucket_interval 未提供 → INVALID_PARAM
```

## 4. 业务事实 Tool（1 个）

### 4.1 `business_metrics` (P2, layer: project)

```yaml
description: |
  直接查询已由 xxl-job 离线任务计算好的指标表（WT_LOW_STRINGS / WT_INVERTER_FAILURE 等）。
  表名硬编码路由——禁止 LLM 自由选表。

input:
  metric_code: 必填（项目字典定义）
  start_time, end_time: 必填
  entity_filter: 可选（设备 ID）

backend: StarRocksBackend

路由（来自 system.business-tables 配置）:
  低效组串:   SELECT * FROM WT_LOW_STRINGS WHERE ...
  故障损失:   SELECT * FROM WT_INVERTER_FAILURE WHERE ...
  限电损失:   SELECT * FROM WT_RESTRICT_INFO WHERE ...
  零电流:     SELECT * FROM WT_INVERTER_STATUS WHERE ...
```

### 5.1 `execute_wt_select` (P0, layer: base_business)

```yaml
description: |

  - 支持聚合函数

    SELECT 部门, COUNT(*) AS 人数 FROM 钛能职工模型 GROUP BY 部门

★ 校验:
  - 必须包含 FROM 关键字
  - 必须使用中文模型名（不许用 tab_* 这种英文物理表名）

    if any in sensitiveList:
```

## 8. 安全护栏 Tool（1 个）

### 8.1 `estimate_count` (P2, layer: metadata)

```yaml
description: |
  估算某时间区间内的扫描行数。超过 system.max-scan-rows（默认 1 亿）拒绝返回明细。
  ★ 所有大查询（time_series / aggregate / execute_wt_select）前必须先调此 Tool。

input:
  tag_filter: 必填（与目标查询一致）
  start_time, end_time: 必填

backend: StarRocksBackend

sql:
  -- 估算行数 = 匹配 tag 数 × 时间跨度 / 采样间隔
  SELECT 
    (SELECT COUNT(*) FROM WT_TAG WHERE tagName REGEXP :tag_filter) AS tag_count,
    -- 默认采样率 5 秒/点（可配 system.sampling-rate-seconds）
    TIMESTAMPDIFF(SECOND, :start_time, :end_time) / :sampling_rate AS estimated_rows

★ 口径警示（第六轮源码）:
  - 派生点位（_1H_/_1D_ 段）重算不删旧行，实际行数可能高于估算——估算结果乘以安全系数 1.5
  - 电量类 tag（tagCode 174 族）是阶跃属性（compdev 压缩），实际行数远低于 5 秒采样估算——估算偏保守可接受
```

## 8.2 ★ 口径溯源三来源（答案"这个数怎么来的"必查，第五+六轮合并）

派生测点/指标的计算口径有**三种来源**，解释答案时先判断属于哪一种：

| 来源 | 识别方式 | 查询入口 |
|---|---|---|
| ① 源测点采集 | tagCode 为 `_1O_` 原始段 | WT_DATA / TSDB |
| ② xxl-job 衍生表 | 派生点 `_1H_/_1D_` 段 / WT_CUBE / 业务事实表 | pvConfig.json + energyConfig.json（classPath/tagCode 映射，热配置） |
| ③ TSDB 服务端 Lua 方程式 | 计算量测点（≤5000 个，Lua 5.3 ≤2048 字节） | `EQQuery` / `NAMEQuery(NameType.EQ)` 枚举；同比环比=`YearOnYear/LinkRelativeRatio`（**累积比值语义，非增长率**） |
